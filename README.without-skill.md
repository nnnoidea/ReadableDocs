# ReadableDocs

**让 Agent 按你的要求，把难懂的说明文档改得清楚、简洁、有重点。**

ReadableDocs 是一个给 Agent 使用的文档写作与改写 Skill，当前版本 **0.0.1**。它先理清内容，再用图说明结构、关系和过程，让读者顺着看就能理解；文字补充必要解释、条件和可复制的操作内容。

适合改写平台介绍、使用说明、研究交接和知识解释，也可以依据材料从头撰写。

## 开始使用

将完整的 [`readable-docs/`](readable-docs/) 目录放到 Agent 可以读取的位置，保留内部文件结构。把原文交给 Agent，并告诉它读者是谁、要看懂什么、哪些内容必须保留。

例如，把下面的路径换成实际路径后发送给 Agent：

```text
请读取并使用 /实际路径/readable-docs/SKILL.md，改写下面的文档。

读者：第一次接触这个工具的同事。
目的：看懂它解决什么问题，并能完成第一次使用。
要求：简洁，先突出用途和操作步骤；术语首次出现时解释。
必须保留：原文中的前置条件、命令和限制，不补造事实。
输出：Markdown 和配套图片，保存到 ./output/。

原文：
[粘贴文档，或提供 Agent 可读取的文件路径]
```

篇幅、语气、输出格式有明确要求时，一并写进去。

## 它会怎样改

| 原文的问题 | 改写方式 |
| --- | --- |
| 铺垫很长，重点藏在后面 | 先呈现用途、主要结论或行动，再展开必要细节 |
| 术语密集，需要来回翻 | 在首次需要时解释概念，把条件放到对应说明旁 |
| 关系和步骤全靠长段文字 | 用关系图、流程图等呈现，配文只补必要信息 |
| 内容很多，却不知道能删什么 | 按读者任务取舍，保留事实、必要条件和适用范围 |

Skill 要求 Agent 先完成文字稿，逐章检查并整体复查；再逐章改成图文，对照改写前后检查并整体复查，最后回查输出。检查覆盖内容是否遗漏、图示是否准确，以及阅读顺序是否清楚。

## 你会得到什么

- **成品文档与配套图示**：按你要求的格式和位置输出。
- **可追溯的过程材料**：草稿、文字定稿、章节改写前后对照、检查记录，以及使用的图源和数据依据。

这是以图解释核心内容的写作方式；命令、公式、精确资料等仍可用文字、代码块或查阅表保留。

## 绘图与运行条件

Agent 需要能读写本地文件。包内的绘图脚本使用 **Python 3 标准库**，将 JSON 内容生成 SVG，提供流程、层级、时序、包含关系和数据图表等模板。

- [Skill 完整说明](readable-docs/SKILL.md)
- [按问题选择图形](readable-docs/references/choosing-figures.md)
- [绘图模板与命令](readable-docs/references/drawing.md)

自带的 PNG 预览脚本需要 macOS Quick Look 和 Pillow；其他系统需使用已有的 SVG 渲染工具。最终可输出的格式也取决于 Agent 环境中的工具。
