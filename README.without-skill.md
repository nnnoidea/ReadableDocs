# ReadableDocs

**让 Agent 按你的要求，把文档改到读得懂、用得上。**

ReadableDocs 是一套供 Agent 使用的文档写作 Skill，当前版本 **0.0.1**。它根据读者、目的和你的限制调整内容，用图讲清结构、关系和过程，让读者通过标题、图和标注抓住重点。

适用于平台介绍、使用说明、研究交接和知识解释。可以从材料新写，也可以改写已有文档，再根据你的反馈继续调整。

## 它会怎样改

| 文档让你困惑的地方 | ReadableDocs 的处理方式 |
| --- | --- |
| 看了很久，还不知道重点 | 先建立主线，再展开当前需要的细节 |
| 术语太多，前后跳着看 | 在概念第一次出现时解释，把条件放在使用处 |
| 大段文字，看不清关系和步骤 | 用图呈现结构、流程、比较或数据，配文辅助读图 |
| 改短之后，关键条件也丢了 | 对照原稿核查事实、适用范围和必要条件 |

## 开始使用

把完整的 [`readable-docs/`](readable-docs/) 目录放到 Agent 可读取的位置，保留其中的脚本、模板和参考文件。将下面提示词中的方括号替换为你的实际内容；`readable-docs/SKILL.md` 也可替换成实际路径。

### 新写一份文档

```text
请读取 readable-docs/SKILL.md，并使用 readable-docs。

根据 [材料路径或粘贴的材料]，写一份 [文档类型]。
读者是 [谁、已经了解什么]，读完需要能 [理解什么或完成什么]。
要求：[篇幅、必须包含的信息、语气等]。
请用图讲清主要关系和过程，突出重点。
交付为 [格式]，保存到 [目录]，保留可编辑源稿。
```

### 改写一份看不懂的文档

```text
请读取 readable-docs/SKILL.md，并使用 readable-docs 改写 [原文路径]。

这份文档给 [读者] 看，目的是 [阅读后要达成的事]。
现在的问题是：[例如术语太多、步骤不清、重点埋在细节里]。
希望改成：[例如先讲用途，再用图解释操作步骤，细节放到查阅处]。
必须保留 [事实、条件或章节]；篇幅控制在 [要求]。
交付为 [格式]，保存到 [目录]，保留可编辑源稿。
```

### 继续追加要求

在同一轮写作对话中，可以直接告诉 Agent 具体哪里仍然难懂：

```text
请继续用 readable-docs 修改刚才的文档。

读者改为第一次接触这个项目的人。
开头先讲“它能帮我做什么”，再解释工作方式。
第二节的关系仍然看不清，请用一张图解释；专业术语首次出现时补充解释。
正文再精简一些，保留关键条件和可直接照做的步骤。
请同步更新写作依据，检查受影响的章节，并更新原交付文件与源稿。
```

## 你会得到什么

- **按约定格式交付的文档**；默认另附 HTML 阅读版，也可明确要求只交付 Markdown 等指定格式。
- **可继续修改的源稿**：Markdown 正文、独立图源、必要数据和生成图。
- **可回看的过程材料**：写作依据、检查记录和版本快照。

Agent 会先检查文字，再制作和检查图文，核对改写是否保留必要信息。你的后续要求会成为继续修改的依据。完整规则见 [`readable-docs/SKILL.md`](readable-docs/SKILL.md)。
