# Readable Docs

为指定读者编写或改写说明性文档，以图为主要表达、文字为辅助，让读者通过标题、图和标注理解主线，配文补足必要解释。

整个过程遵循两个阅读前提：

- 阅读有顺序。概念在首次需要时得到解释，读者才能顺着理解后文。
- 读者能同时记住的信息有限。每引入一个概念、条件或例外，都在增加理解负担。

## 工作流程与过程文件

先明确目的、读者和限制，完成整篇文字草稿，用于理清内容和核对事实。随后逐步完成四个检查阶段：**逐章自查文字 → 整体复查文字 → 逐章自查图文 → 整体复查图文**，最后输出并回查。进入图文阶段后，按核心说明点重新组织表达。

过程材料保存在两份 Markdown 中：

- **草稿文件**：开头记录目的、读者和限制，之后保存正文，并引用图源与数据依据。
- **检查记录文件**：随执行过程，按阶段、章节分别记录检查发现、实际修改与复查结论，保留前轮记录。

每个阶段都以当前实际保存的稿件为输入。完成检查与必要修改后，Agent 重新读取修改后的稿件，根据实际阅读结果填写复查结论；通过后才开始下一阶段。逐章检查时，一次完成一章后再处理下一章；整体复查时，重新读取上一阶段完成后的全文。原稿已满足要求时，记录检查依据后继续。

## 1. 明确文档目的、读者和限制

先创建草稿 Markdown，在开头写下三项写作依据：

- **文档目的**：读者读完后需要理解什么、作出什么判断或完成什么事。
- **读者群体**：写给谁，他们以什么身份、在什么场景下阅读，要完成什么阅读任务；再说明已有知识和需要解释的内容。据此决定内容取舍与细节深度。
- **写作限制**：记录用户给出的限制（如有）；没有明确限制时如实注明。

依据用户要求和提供的材料填写，推断内容明确标注。会影响写作方向且无法合理确定的信息，应先澄清。后续写作和检查始终以这三项为准；用户调整要求时，同步更新写作依据。

## 2. 完成并保存文字草稿

在写作依据之后写“文档草稿”，完成并保存整篇文字正文，再进入第 3 步填写自查表。写作时遵循以下原则：

1. 先让读者知道在讨论什么。介绍对象时先说明它是什么；分析问题时先点明问题，再按读者需要安排背景、结论和证据。
2. 先建立主干，再按需要展开。先给读者整体认识或主要结论，再按当前阅读任务引入机制、证据、特殊情况和操作细节。
3. 按理解收益取舍文字。保留帮助读者理解、判断或行动的内容，以及能减少猜测的解释和例子；删去其余文字。
4. 概念先解释，再使用；解释到当前够用即可。首次出现时说明含义，按当前理解需要引入术语；熟悉的说法足以表达时，直接使用熟悉的说法。
5. 术语保持一致，必要时帮助读者重新想起。同一对象使用稳定的名称；概念隔了较长篇幅再次出现时，可以补一句短解释。
6. 解释靠近使用，减少跨段依赖。相关的概念、条件和例子放在一起。一段话集中解决一个问题，当前结论所需的限定在附近可见。
7. 写清必要条件。会改变结论、适用范围或读者行动的条件，紧贴对应结论。实现细节按读者需要安排在相关说明中，简化后的表达保持事实准确。
8. 按信息作用安排视觉层级，再选择排版。标题用于定位，段首呈现重点，段落组织解释，列表承载并列条件或步骤，表格用于比较，附录（如有）保留查阅资料。
9. 直接、正向地表达。围绕读者当前需要理解或完成的事，说明是什么、怎样做、何时适用。必要限制和证据边界用具体事实与条件说明。

## 3. 阶段一：逐章自查文字

另建检查记录 Markdown，引用草稿文件及其写作依据。按草稿的章节标题组织记录，每章一张自查表。

从第一章开始，一次检查一章。对照写作依据，检查以下四项：

- **目的**：本章是否有助于达成文档目的？有没有遗漏关键内容或偏离目的？
- **限制**：本章是否满足写作限制？事实是否有依据，必要条件是否保留？没有明确写作限制时如实注明，仍核对事实和必要条件。
- **读者群体**：本章内容是否服务目标读者的身份、场景和任务？重点、细节深度及知识前提是否合适？删除某部分会影响他们理解、判断或完成什么？
- **顺序表达**：按下面四个问题逐句检查。

检查顺序表达时，只看当前句子及它前面的内容，问：

1. 读者现在知道这些词是什么意思吗？
2. 这句话要求他同时记住多少东西？
3. 这些条件和细节现在就需要吗？
4. 删掉或展开这句话，理解会更容易还是更困难？

每章使用三列 Markdown 表格，简要记录检查结果：

| 检查项 | 发现与修改 | 复查结论 |
| --- | --- | --- |
| 目的 | — | — |
| 限制 | — | — |
| 读者群体 | — | — |
| 顺序表达 | — | — |

每格写短句；有多个发现时用编号区分，顺序表达可引用上面的问题序号。不适用或无法确认时明确注明。

每章按以下顺序执行：

1. 阅读当前章节，按四项检查，将发现的问题先记入检查记录，复查结论暂记“待修改”。没有问题的项简述判断依据，注明“原稿已满足”。
2. 有问题就修改草稿中的该章，保留事实成立所需的条件和读者行动所需的信息；在检查记录中补充实际删改，保留原问题。
3. 保存修改后，Agent 重新读取修改后的当前章节，按四项复查，再根据实际阅读结果更新结论。仍有问题就继续修改、复查；本章各项满足后进入下一章。本章原稿已满足时直接进入下一章。

若缺少完成当前写作所必需的信息，且无法依据现有材料准确表述，记为待确认，列明所需信息，补齐后再复查。原材料本身尚未解决的问题，如实说明已知范围与未知之处，检查这些说明是否准确、充分后继续。

以读者理解所需的精力衡量表达效果。各章文字检查通过后，进入文字整体复查。

## 4. 阶段二：整体复查文字

各章文字检查完成后，重新读取实际保存的完整文字稿，从头到尾阅读，对照目的、限制、读者群体和顺序表达，检查全文是否完成阅读任务，章节衔接是否顺畅，是否有跨章重复、遗漏或先用后解释的概念。

将发现写入独立检查记录的“文字整体复查”部分。有问题就修改相关章节，沿用第 3 步的检查、修改、复查顺序，同步更新章节记录，再复查对全文的影响。无问题时简述判断依据。文字整体复查通过后，再进入图文阶段。

## 5. 阶段三：逐章自查图文

按章节顺序，将已通过整体复查的文字转为以图为主的表达。先识别本章需要读者理解的核心说明点，为每一点安排视觉表达，再围绕图组织少量配文。完成本章图文自查、修改和复查后，再处理下一章。

能用图表达的内容尽量交给图。结构、关系、步骤、条件、变化和比较由视觉布局直接呈现；定义、原因和行动中能够画清的部分同样转成图。文字只补充读图所需的引导、图中难以表达的解释、精确条件和证据。每章按以下要点处理：

1. **每个核心说明点默认用图表达。** 找出需要读者看见的对象、关系、顺序或变化，确定图要回答的问题。局部组成、简单联系和一个步骤的机制也可以成图；相关说明点可以合用一张图，通过总览与局部图展开细节。纯文字表达更有助于理解的部分，在本章检查记录中简述保留原因。
2. **按信息关系选择表达形式。** 组成与包含用框内布局，关联用连线，有方向的依赖或流转用箭头，数值关系采用相应数据图表。精确数值和逐项查阅资料可保留表格。

   选图时先读取[按读者问题选图](references/choosing-figures.md)，再从[绘图模板目录](references/drawing.md)选择模板。读取选中的 JSON，填入对象、关系、条件和数据，由源码生成统一布局。优先通过选模板、拆分说明点或调整模板参数完成；仍无法准确表达时，再在任务目录定制绘制，沿用 ReadableDocs 的统一风格，并在检查记录中说明模板缺少的能力。

3. **让视觉布局直接说明含义。** 用位置、包含、连接、方向、长度或比例呈现关系与差异，框内放简短、具体的标签。每张图回答一个清楚的问题；总览建立整体认识，局部图解释其中的具体关系或机制。
4. **图也遵守阅读顺序和上下文限制。** 图中的对象和术语在出现时得到解释，阅读方向及箭头、颜色、符号的含义清楚。按读者能同时理解的范围安排对象和关系，所需解释在当前位置可见。
5. **视觉表达忠于事实。** 关系、顺序和必要条件有材料依据。数据图表明确适用的单位、时间范围和统计口径，坐标、比例、颜色如实呈现数值与差异。
6. **围绕图重写辅助文字。** 图完成后，删除已由图表达的正文，保留帮助读者理解意义、依据或适用条件的短说明。影响结论的必要条件放在图内或紧邻图的位置；需要复制、精确核对的数值和资料，可集中保留在查阅表格或附录（如有）。
7. **先看图能否讲清，再检查图文合读。** 查看实际渲染，只读标题、图和标注，检查是否能理解本章主线、主要关系和结论；缺少的视觉表达继续补图或调整。再与配文合读，核对事实、术语、条件和可读性。表达不清时，优先简化布局、拆图、换图型或补就近说明；经调整仍由文字表达更清楚的部分，注明原因后采用文字。

在草稿 Markdown 中保留图的源代码或数据依据；独立资源文件由草稿引用。沿用第 3 步的检查、修改、复查顺序，更新本章四项自查记录：核心说明点由哪些图承载、纯文字部分的保留原因及理解收益归入目的和读者群体，事实与条件归入限制，术语、阅读方向、渲染和图文重复归入顺序表达。本章复查通过后进入下一章。

## 6. 阶段四：整体复查图文

各章图文自查通过后，重新读取实际保存的完整图文稿，从头到尾阅读并查看实际图示，重新核对目的、限制、读者群体和顺序表达，重点检查：

- 章节衔接是否顺畅？是否有跨章重复、关键遗漏或先用后解释的概念？
- 连续看标题、图和标注，能否理解全文主线、主要关系与结论？哪些核心说明点仍主要依靠长段文字？
- 各图是否帮助读者回答当前问题，减少查找、记忆或推理？仅靠配文讲清的关系或变化，怎样直接呈现在图中？
- 哪些段落、列表或表格还能转成图？纯文字部分的保留原因是否成立？
- 图中的关系、数值和必要条件是否准确、完整？
- 图已表达的内容是否从正文删去？剩余配文是否只承担必要的引导、解释、条件和证据？术语是否就近说明？

将发现写入检查记录的“图文整体复查”部分。发现可视化机会就补图或调整已有图，并删改被图接替的文字；其他问题修改相关章节。涉及章节的修改沿用第 3 步的检查、修改、复查顺序，并同步更新该章检查记录。随后复查对全文的影响，图示变化须查看实际渲染，直到各项满足。无问题时简述判断依据。

## 7. 输出文档并回查

最终检查通过后，以检查后的 Markdown 正文和图示为依据，按用户要求的格式与目标位置输出文档。回查最终内容和实际呈现，确认转换没有遗漏信息或影响阅读。

将输出回查结果写入检查记录文件。交付正文取自草稿中的“文档草稿”部分及其图示；写作依据和检查记录保留为本地过程材料。
