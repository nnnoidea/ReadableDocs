# Readable Docs

为指定读者编写或改写说明性文档，让图承担核心说明。读者通过标题、图和标注理解主线、机制与结论；文字用于辅助读图，或承载确实无法用图清楚表达的必要信息。

整个过程遵循两个阅读前提：

- 阅读有顺序。概念在首次需要时得到解释，读者才能顺着理解后文。
- 读者能同时记住的信息有限。每引入一个概念、条件或例外，都在增加理解负担。

## 执行顺序与记录

先明确写作依据——文档目的、读者群体和写作限制，再依次完成两轮工作：

1. **文字轮：完整文字稿 → 逐章自查文字 → 整体复查文字 → 保存文字定稿。**
2. **图文轮：逐章画图并改配文、保存前后配对稿 → 逐章自查图文 → 整体复查图文。** 全部章节的图文改写和配对保存完成后，再开始图文检查。

两轮完成后，按第 8 步检查并交付文档。保留由 Markdown 正文、独立图源、必要数据和生成图组成的**源稿包**，默认额外提供 HTML 阅读版。

执行中维护三类材料：

- **当前稿件与写作依据**：初稿把写作依据和完整正文放在同一 Markdown 中。初稿完成后切章，后续正文修改到章节文件，依据维护在 `brief.md`，全文由章节汇总。
- **检查记录 `review.md`**：按四个检查阶段及章节，随执行记录发现、实际修改和复查结论，保留前轮记录。已有判断依据可以引用，每轮仍记录实际复查结果。
- **版本快照**：保存当时的稿件、图源和渲染。文字定稿独立保留；图文改写逐章保存改前、改后的一对快照；后续修改另存修订版本。

四个阶段共用同一复查顺序。原稿已满足时，在现有自查表中简述依据。有修改时，依次完成：

1. **记录问题，修改并保存。** 在“发现与修改”列写明问题与实际改动，“复查结论”暂记“待复查”。
2. **单独读回保存后的稿件。** 图源有改动时，先重新生成图示。再让当前章节正文完整返回给 Agent，按读者的顺序一起查看实际渲染的图、配文和相邻内容。整体复查时重新汇总并读回全文，长稿可按顺序分段读取。
3. **读完再判断。** Agent 根据刚读到的稿件逐项判断。已解决的问题，在“复查结论”中写一句能回到稿件核对的结果；仍有问题就再次修改、保存和读回。脚本可执行编辑和文件校验，语义结论留给读回后的 Agent 填写。当前章通过后再检查下一章，整体通过后再进入下一步。

## 1. 明确文档目的、读者和限制

先创建初稿 Markdown，在开头写下三项写作依据：

- **文档目的**：读者读完后需要理解什么、作出什么判断或完成什么事。
- **读者群体**：写给谁，他们以什么身份、在什么场景下阅读，要完成什么阅读任务；再说明已有知识和需要解释的内容。据此决定内容取舍与细节深度。
- **写作限制**：记录用户给出的限制（如有）；没有明确限制时如实注明。

依据用户要求和提供的材料填写，推断内容明确标注。会影响写作方向且无法合理确定的信息，应先澄清。后续写作和检查始终以这三项为准；用户调整要求时，同步更新写作依据。

根据用户要求和已有上下文确定交付格式与位置，记在写作依据中。用户已明确的选择直接沿用；目标平台的图示、嵌入与编辑能力在选用时核实。HTML 默认作为额外阅读选项；用户明确只需要某种产物时，按其要求交付，源稿包继续保留。

## 2. 完成并保存文字草稿

在写作依据之后用 Markdown 标题“文档草稿”分隔正文，完成并保存整篇文字稿。写作时遵循以下原则：

1. 先让读者知道在讨论什么。介绍对象时先说明它是什么；分析问题时先点明问题，再按读者需要安排背景、结论和证据。
2. 先建立主干，再按需要展开。先给读者整体认识或主要结论，再按当前阅读任务引入机制、证据、特殊情况和操作细节。
3. 按理解收益取舍文字。保留帮助读者理解、判断或行动的内容，以及能减少猜测的解释和例子；删去其余文字。
4. 概念先解释，再使用；解释到当前够用即可。首次出现时说明含义，按当前理解需要引入术语；熟悉的说法足以表达时，直接使用熟悉的说法。
5. 术语保持一致，必要时帮助读者重新想起。同一对象使用稳定的名称；概念隔了较长篇幅再次出现时，可以补一句短解释。
6. 解释靠近使用，减少跨段依赖。相关的概念、条件和例子放在一起。一段话集中解决一个问题，当前结论所需的限定在附近可见。
7. 写清必要条件。会改变结论、适用范围或读者行动的条件，紧贴对应结论。实现细节按读者需要安排在相关说明中，简化后的表达保持事实准确。
8. 按信息作用安排视觉层级，再选择排版。标题用于定位，段首呈现重点，段落组织解释，列表承载并列条件或步骤，表格用于比较，附录（如有）保留查阅资料。
9. 直接、正向地表达。围绕读者当前需要理解或完成的事，说明是什么、怎样做、何时适用。必要限制和证据边界用具体事实与条件说明。

完整文字稿保存后，按[过程文件工具](references/workflow-tools.md)切章并保存初稿快照，再进入第 3 步。此后直接修改章节文件，由工具汇总全文、保存快照和生成差异。内容判断由 Agent 完成。

## 3. 阶段一：逐章自查文字

创建独立的 `review.md`，引用当前章节文件和 `brief.md`。按阅读顺序组织章节记录，每章一张自查表。

从第一章开始，一次检查一章。对照写作依据，检查以下四项：

- **目的**：本章是否有助于达成文档目的？有没有遗漏关键内容或偏离目的？
- **限制**：本章是否满足写作限制？事实是否有依据，必要条件是否保留？没有明确写作限制时如实注明，仍核对事实和必要条件。
- **读者群体**：目标读者在这里要理解什么、判断什么或做什么？按其身份、场景和已有知识确定细节深度。当前判断所需的信息放在前面，后续才用的明细放到使用处或查阅表。
- **顺序表达**：按下面四个问题逐句检查。

检查顺序表达时，只看当前句子及它前面的内容，问：

1. 读者现在知道这些词是什么意思吗？
2. 这句话要求他同时记住多少东西？
3. 这些条件和细节现在就需要吗？
4. 删掉或展开这句话，理解会更容易还是更困难？

在目标读者需要解释的术语第一次出现处停下，标题、表头、公式和图内标签都算。只凭读到这里的内容，读者能说清它的含义吗？若不能，把释义移到首次使用之前，或在首次出现处直接解释。

每章使用三列 Markdown 表格，简要记录检查结果：

| 检查项 | 发现与修改 | 复查结论 |
| --- | --- | --- |
| 目的 | — | — |
| 限制 | — | — |
| 读者群体 | — | — |
| 顺序表达 | — | — |

每格写短句；有多个发现时用编号区分，顺序表达可引用上面的问题序号。不适用或无法确认时明确注明。

每章按以下顺序执行：

1. 阅读当前章节，按四项检查，将发现的问题先记入检查记录。没有问题的项简述判断依据，注明“原稿已满足”。
2. 有问题就修改该章文件，保留事实成立所需的条件和读者行动所需的信息；在检查记录中补充实际删改，保留原问题。
3. 保存修改后，Agent 重新读取修改后的当前章节，按四项复查，再根据实际阅读结果更新结论。仍有问题就继续修改、复查；本章各项满足后进入下一章。本章原稿已满足时直接进入下一章。

若缺少完成当前写作所必需的信息，且无法依据现有材料准确表述，记为待确认，列明所需信息，补齐后再复查。原材料本身尚未解决的问题，如实说明已知范围与未知之处，检查这些说明是否准确、充分后继续。

各章文字检查通过后，进入文字整体复查。

## 4. 阶段二：整体复查文字

各章文字检查完成后，先汇总当前章节，再重新读取保存的完整文字稿，从头到尾阅读，对照目的、限制、读者群体和顺序表达，检查全文是否完成阅读任务，章节衔接是否顺畅，是否有跨章重复、遗漏或先用后解释的概念。

将发现写入 `review.md` 的“文字整体复查”部分。有问题就修改相关章节，沿用第 3 步的检查、修改、复查顺序，同步更新章节记录，再复查对全文的影响。无问题时简述判断依据。通过后保留这份文字定稿，作为制作和检查图文稿的内容依据。

## 5. 逐章画图并改配文，保存前后配对稿

以第 4 步保存的文字定稿为依据，从第一章开始，一次改写一章。本节产出各章的前后配对稿和完整图文初稿，供第 6 步检查。绘制时同时追求两个目标：重点更突出、更易懂；画面更好看。

结构、关系、步骤、条件、变化、比较，以及能画清的定义、原因和行动，都由图承担。配文用于辅助读图，或保留经视觉表达调整后仍确实无法用图清楚表达的必要信息。

每章按以下顺序完成：

1. **保存改前稿，确定图要说明什么。** 保存本章文字全文。逐个找出需要读者看见的对象、关系、顺序、条件或变化，明确“读者看完这张图，应当看出什么”，记在已有过程材料中。局部组成、简单联系和一个步骤的机制也安排图示；相关说明点可以合用一张图，通过总览与局部图展开细节。
2. **选择表达形式与模板。** 先按[读者问题选图](references/choosing-figures.md)，再从[模板目录](references/drawing.md)选择实现。位置、包含、连线、箭头、长度和比例分别承担相应含义；多种关系共同表达时，按需使用[组合布局与视觉组件](references/composing-figures.md)。优先通过模板、拆分说明点或调整参数完成；仍无法准确表达时，在任务目录定制绘制，沿用统一风格，并在后续检查中说明模板缺少的能力。
3. **填入内容与依据。** 读取选中的 JSON，填写对象、关系、条件和数据。关系、顺序及必要条件有材料依据；数据图明确单位、时间范围和统计口径，坐标、比例和颜色如实呈现差异。需要精确复制、逐项核对的字段、数值、公式和代码保留查阅表或代码块，其中需要理解的关系、计算过程和使用条件仍安排图示。
4. **生成图示，落实重点与阅读顺序。** 材料支持结论时，标题直接点明主要发现；解释机制时，标题点明要回答的问题。框内用简短具体的标签，条件放在对应分支或对象旁。比较对象对齐，前后变化配对，目标差距就近标出，关键路径保持连续；用强调色和线条层级突出重点，背景信息保持可读，平等比较的对象保持同等突出。标签靠近对象，优先标出当前问题需要的终点、转折、差值或阈值。

   对象和术语在出现时得到解释，阅读方向及箭头、颜色、符号的含义清楚；按读者能同时理解的范围安排对象和关系。同一对象跨图保持一致的名称和颜色含义。按内容选择横向或纵向布局，相关对象靠近、信息组之间留出空间，统一字号、对齐、线条和色块分隔。复杂说明拆成总览与局部图。

5. **改写配文。** 删除已由图表达的正文。用一个具体问题概括每段配文；一段回答多个问题时，按问题拆开，再分别选择图、短段或查阅表。必要条件放在图内或紧邻对应图的短注中。需要复制的原文、公式、代码和精确资料放在就近查阅位置或附录（如有）。在后续“配文作用”项说明各段辅助哪张图，或为什么这项必要信息只能用文字表达。
6. **保存改后稿。** 将图、标注、配文和查阅资料放到实际阅读位置，保存本章完整图文稿及对应资源，再处理下一章。工具按同一章节标识保存配对，如 `pairs/01/before/` 与 `pairs/01/after/`，保留该次改写的图源、数据依据和渲染。

全部章节完成后，汇总并保存完整图文初稿，再进入第 6 步逐章检查。

## 6. 阶段三：逐章自查图文

本阶段检查图文化是否保住必要信息，并让表达更容易理解。以第 5 步保存的章节配对稿为输入，从第一章开始，一次检查一章。目的、读者和限制作为判断依据，使用以下四项图文检查：

- **信息保留**：逐项对照改前稿，事实、必要条件、适用范围及其含义是否完整保留在图或配文中？触发条件、时间限定和数值口径是否一致？删改是否符合既定写作要求？
- **图示表达**：分别记录两个判断。**理解效果**：只读标题、图和标注，是否先看到重点，并直接看出本图要表达的关系、机制、条件或结论？标签是否就近对应，图形是否准确，框内长句是否需拆图？**视觉效果**：按文档阅读宽度查看，画面比例、对齐、留白、文字与颜色是否协调、清爽、易读？
- **配文作用**：每段文字辅助哪张图、补充什么必要信息？独立保留的内容是否确实无法用图准确、清楚表达，理由是否成立？
- **图文合读**：在术语首次出现处停下，仅凭此前及此处的图文，读者能否理解它？条件是否就近可见？图文有无重复、冲突或理解断点？每段配文能否用一个具体的读者问题概括？

在 `review.md` 中引用本章配对稿，使用图文自查表：

| 检查项 | 发现与修改 | 复查结论 |
| --- | --- | --- |
| 信息保留 | — | — |
| 图示表达 | — | — |
| 配文作用 | — | — |
| 图文合读 | — | — |

每章按以下顺序执行：

1. 读取改前稿、改后稿并查看实际图示，按本节四项检查。先记录发现；已满足的项记录判断依据。信息删改注明依据及必要信息在图或配文中的对应位置；保留文字的理由写在“配文作用”项，定制图原因写在“图示表达”项；已有依据直接引用。
2. 根据发现修改本章。图示承担不足时补图、拆图或换图型；需要文字承载的必要信息保留在适当位置。保留第 5 步的原配对稿及资源，另存修订结果并更新完整稿。
3. 重新读取修改后的章节、查看更新后的实际图示，按本节四项复查，再填写结论。仍有问题就继续修改、复查；本章满足后检查下一章。

## 7. 阶段四：整体复查图文

各章图文自查通过后，先汇总当前章节，再重新读取保存的完整图文稿，从头到尾阅读并查看实际图示。以目的、读者和限制为依据，沿用第 6 步的四项图文检查，重点核对全文：

- **信息保留**：对照文字定稿，关键内容和必要条件是否完整，分散在不同章节的事实、范围和数值口径是否一致？
- **图示表达**：连续看标题、图和标注，能否理解全文主线、核心机制、关键条件与结论？各图重点是否服务全文主线，跨图颜色含义、字号层级和视觉风格是否一致，画面是否协调？仍依赖正文的说明点分别需要补什么图？
- **配文作用**：逐段核对辅助作用与独立保留理由，哪些段落、列表或表格还可以交给图？图已表达的内容是否从正文删去？
- **图文合读**：章节衔接是否顺畅，有无跨章重复、冲突或理解断点？术语是否先解释再使用，条件是否在读者需要的位置可见？

将发现写入 `review.md` 的“图文整体复查”部分。发现可视化机会就补图或调整已有图，并删改被图接替的文字；其他问题修改相关章节。涉及章节的修改按第 6 步检查、修改、复查，并同步更新该章记录。随后复查对全文的影响，图示变化须查看实际渲染，直到各项满足。无问题时简述判断依据。

## 8. 输出文档并回查

最终检查通过后，按[源稿包与交付](references/delivery.md)整理 Markdown 正文、独立图源、必要数据和生成图，以相对路径连接，作为后续修改与换平台的依据。正文由当前章节文件汇总；写作依据和检查记录独立保留。

先从定稿生成本地 HTML，核对转换完整性，并在桌面阅读宽度下查看排版。发现问题就修改源稿，重新生成并检查 HTML。检查通过后，用同一份定稿生成第 1 步约定的交付物；目标是 HTML 时直接使用已检查的阅读版。

交付飞书时，发布后用 API 回读正文和图片，与发布稿核对。只有用户明确要求看飞书实际效果时，才连接浏览器查看飞书页面。其他格式用对应工具回查。

将输出回查结果写入检查记录。交付时标明用户要求的文档、额外 HTML（如有）与源稿包的位置。后续切换平台时，先核对现行文档与源稿包的差异、合并确认的修改，再从当前源稿生成新版本。
