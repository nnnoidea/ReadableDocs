# 源稿包与交付

以 Markdown＋图源作为持续维护的源稿，从同一源稿生成用户要求的文档，默认额外提供 HTML 阅读版。目标格式与位置沿用写作依据中的约定；目标本身是 HTML 时复用阅读版，用户明确只需要某种产物时按其要求交付。平台能力在实际选用时通过对应工具或文档核实。

## 1. 整理源稿包

```text
source/
  brief.md             # 当前目的、读者、限制及交付约定
  chapters.json        # 章节顺序及文件
  intro.md, 01.md, …    # 持续维护的章节
  document.md          # 从当前章节汇总的读者正文
  figures/
    overview.json      # 图的内容与关系；定制图保留绘图源码
    overview.svg       # 与当前正文一致的生成图
  data/                # 绘图依赖的原始数据，如有
  document.html        # 默认额外生成的阅读版
```

正文使用相对引用，例如 `![候选通过哪些条件](figures/overview.svg)`。原始截图、附件和必要样式也保存在包内，定制图附上所需的依赖说明。图源、生成图和正文保持一致，资源齐全、图文检查完成后再输出。

`document.md` 只含读者正文，写作依据在 `brief.md`；阶段快照、章节配对和检查记录按[过程文件工具](workflow-tools.md)独立保留。

## 2. 生成本地 HTML 阅读版

从定稿生成 HTML，作为发布前的排版预览。HTML 使用共同字体、色彩、留白和图表样式，目录固定在桌面端左侧，可独立滚动和跳转章节；文档标题、强调色编号与细分隔线组织目录层级，正文在右侧阅读。

生成 HTML 需要 Python 3 和 Pandoc。已有 `pandoc` 命令时直接使用；也可在运行脚本的 Python 环境安装带转换器的包：

```sh
python3 -m pip install pypandoc_binary
```

`SKILL_DIR` 替换为本 Skill 的实际路径。以下命令生成同目录的 `document.html`：

```sh
python3 SKILL_DIR/scripts/export_html.py source/document.md
```

需要另存位置或指定浏览器标签标题时：

```sh
python3 SKILL_DIR/scripts/export_html.py source/document.md output/readable.html --title "文档标题"
```

转换支持章节、列表、表格、代码块、脚注、链接和数学公式。公式转换为 MathML，本地图和样式内嵌到单个 HTML，阅读正文无需联网。复杂图先生成 SVG/PNG，远程图片先保存到源稿包；图片缺失时命令报错，已有 HTML 保持不变。

代码块保留为代码，原始 HTML/TeX 片段按文本处理，公式按数学语法转换。外链保留，本地附件链接相对于输出位置调整。分享单个 HTML 时，正文、图片和样式完整；需要访问本地附件时，一并分享源稿包。

## 3. 检查排版，再交付并回查

先运行机械完整性检查：

```sh
python3 SKILL_DIR/scripts/check_document.py source/document.md source/document.html --output integrity.json
```

命令核对本地资源、正文文本、表格单元格及顺序、代码块、链接、内部锚点，以及图片内容和内嵌情况。省略 HTML 参数时，只检查源稿资源。失败时返回非零退出码并报告具体差异；修正后重新生成并核对。

**排版看本地 HTML。** 用本地预览或渲染截图，在桌面阅读宽度查看目录、标题层级、图与配文的位置，抽查复杂表格、公式和代码块的可读性。发现问题就修改源稿，重新生成 HTML 并复查。通过后，使用同一份定稿生成约定的交付物。

**飞书内容用 API 回读。** 发布后读取目标文档，按阅读顺序与发布稿核对标题、正文、表格、公式、代码和链接。按图片块的顺序下载图片，与对应发布图逐张核对内容和尺寸；文件哈希一致即可确认，相同像素的重新编码图片也可确认。缺块、错序或图像不符时修正并回读受影响的部分。

**用户明确要求看飞书实际效果时**，才额外连接浏览器查看飞书页面。连接只尝试一次，设置短超时（如 15 秒）；工具无法限制等待时，选用支持超时的连接方式，或直接说明本次无法预览。连接失败、超时或页面不可访问，即结束飞书预览，交付已有的 HTML 排版和 API 核对结果，并注明飞书页面未目视核验。

其他目标格式用对应平台工具回查。将实际检查方式、结果和未能核验的范围写入 `review.md`。

机械检查确认转换完整性；事实含义、信息必要性和图示效果由 Agent 按主 Skill 检查。交付时标明目标文档、额外 HTML（如有）及源稿包的位置，可用过程文件工具生成索引。

## 4. 后续修改与迁移

用户可能继续在目标文档中编辑。再次输出或切换平台前，读取现行版本，与源稿比较并合并确认的修改，再从更新后的源稿生成文档。目标文档的修改由对应平台工具读取，HTML 命令负责从当前源稿重新输出。

转换依据：[Pandoc 手册](https://pandoc.org/MANUAL.html)；Python 安装入口：[pypandoc-binary](https://pypi.org/project/pypandoc-binary/)。
